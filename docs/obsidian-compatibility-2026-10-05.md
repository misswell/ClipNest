# ClipNest 功能完善与 Obsidian 对照

日期：2026-10-05。基于当前 `Sources/` 的 120 个 Swift 文件、存储与编辑调用链，以及单元和界面测试。本轮在上一轮代码审查的修复上继续实现本地知识库功能。代码留在工作区，尚未提交、推送或发布；已有 `Promo/` 保留。

## 已修复的实际问题

- 两端补齐重命名入口，界面标题、导航和文件树跟随新文件名；正文一级标题仍由 Markdown 编辑器独立编辑。
- 重命名、移动文件和文件夹时，维护引用它们的 Markdown、Canvas 和 Base 文档。普通链接与图片按新位置重算路径，保留别名、标题和块锚点，跳过代码示例；稳定的别名链接在普通重命名后保持原样。
- 文件操作先准备修改内容，再进入协调写入；失败回滚，并在回滚前检查是否发生其他编辑。保存队列跟随移动路径，删除后的排队保存不会重新创建文件。
- 首次点击别名链接也能解析，不要求先打开知识库页面；缺失的笔记可通过确认入口创建并打开，路径限制在当前 vault 内。
- 合并笔记会重写引用、保留两个正文、重算来源正文中的相对链接，最后把来源移入可恢复的回收站；重复标题会阻止合并，避免标题链接指向错误位置。
- 修复 Canvas 在桌面切换文件时沿用旧画布状态的问题。编辑保留未识别的 JSON 字段与节点类型，未知节点不提供破坏性的内容编辑。
- Base 排序现在使用实际属性值，包括未显示的排序列；支持数字排序、多列排序与分组。复杂属性和附件上的单元格不写入错误的顶层属性。
- YAML 属性使用固定版本的 Yams 解析，区分字符串、数字、布尔、列表与对象；拒绝语法错误、重复顶层键、非有限数字和过深嵌套。属性修改保留正文、其他字段、注释和 YAML 锚点引用。重写链接后再次验证属性/Base 的 YAML；例如新名称中的引号会破坏已有 YAML 字符串时，拒绝操作并保留文件。

之前报告中的移动链接和内部链接问题已在本轮处理；更细的兼容边界见下表。

## 核心功能对照

“已实现”表示有可使用的本地入口与实现；“部分”表示支持所列子集，并不意味着与 Obsidian 完全等价。对照依据为 [Obsidian 官方核心插件列表](https://obsidian.md/help/Plugins/Core%2Bplugins)。

| 功能 | 当前实现 | 兼容边界 |
| --- | --- | --- |
| 文件管理、编辑、预览 | 新建、重命名、移动、回收站、编辑/分栏/预览、交互待办、附件预览 | 平台布局不同；本轮未做真实 iCloud 多端冲突验收 |
| 内部链接 | Wikilink、显示别名、普通本地链接、标题/块锚点、缺失笔记创建 | 同名且无法确定目标时不会猜测；未实现所有链接自动补全语法。依据 [内部链接文档](https://obsidian.md/help/links) |
| 别名、标签、属性 | YAML 类型解析、原文属性编辑、嵌套标签浏览与搜索 | 属性类型管理和批量编辑未达到完整 Properties 插件水平 |
| 大纲 | 笔记详情列出标题并跳转 | 尚无独立持久侧栏和完整标题折叠体验 |
| 反向链接、出链 | 列表、未链接提及、关联笔记预览与跳转 | 大型/未下载笔记的索引有明确限制；依据 [Backlinks](https://obsidian.md/help/plugins/backlinks) |
| 全局/局部关系图 | 实际链接边、缩放、点击打开、局部邻居 | 使用环形布局，最多显示 120 个节点；无力导向、复杂分组和动画参数 |
| 搜索 | 现有全文索引；知识库支持 `tag:`、`path:`、`file:`、属性过滤和负向词 | 尚未完整支持 Obsidian 全部搜索运算符和保存搜索 |
| 书签 | 笔记书签，按 vault 隔离，移动后维护路径 | 标题、搜索、书签分组和多笔记组合尚未实现 |
| 日记 | 按文件夹/日期格式创建或打开，可用模板；不覆盖已有日记 | 支持常见日期格式，不是完整 Moment.js 格式引擎 |
| 模板 | 模板目录、插入、日期/时间/标题变量、保留现有属性 | 同名属性由现有笔记优先，未实现全部属性列表合并规则 |
| 快速切换、命令面板 | 现有快速打开；新增创建、日记、随机笔记、知识库等命令 | 命令数量与可配置快捷键尚未覆盖所有 Obsidian 操作 |
| 笔记恢复 | 自动保存前快照、历史预览、恢复，最多 50 个版本 | 是本应用本地历史格式，不读取 Obsidian 的私有恢复数据库 |
| 笔记嵌入、Callout、脚注 | 整篇/标题/块嵌入、折叠 Callout、脚注定义与跳转 | 嵌入深度上限 2；高级数学公式、Mermaid 图、复杂列表块嵌入仍有差距 |
| Canvas | 新建、文本/文件/链接/分组卡片、拖动、尺寸编辑、连接和删除 | 基于 [JSON Canvas 1.0](https://jsoncanvas.org/spec/1.0/) 保留未知字段；暂不支持全部箭头、连线样式、嵌套分组和画布交互 |
| Slides | 按代码块外分隔线生成演示页，前后切换 | 不包含 Obsidian 全部主题、导出和演示配置 |
| Note composer | 合并整篇、按标题提取章节和子章节，维护相对链接与恢复 | 暂不支持任意选区提取；提取后其他笔记指向旧章节的锚点不会自动迁移到新笔记。依据 [Note composer](https://obsidian.md/help/Plugins/Note%2Bcomposer) |
| 录音 | 用户点击后申请权限，录制/停止/导入附件，预览播放 | 存储路径已测试；真实麦克风权限、音质和后台录音未做真机验收 |
| Workspaces | macOS 保存/载入标签页、选中项、侧栏、终端宽度/显示和编辑模式 | 不重启运行中的终端命令；未覆盖移动端布局、跨窗口工作区和所有布局结构。依据 [Workspaces](https://obsidian.md/help/plugins/workspaces) |
| Bases | `.base` 文件及嵌入、表格/列表/卡片、多视图、全局/视图过滤、公式、排序、分组、常见汇总、顶层属性编辑 | 支持常用表达式和文件元数据；日期/链接对象体系、链式高级函数、插件视图和自定义汇总仍未完整实现；不支持的表达式明确报错。依据 [Bases 语法](https://obsidian.md/help/bases/syntax) |

## 使用入口

- iPhone/iPad：底部“知识库”；笔记“更多 → 笔记详情”查看属性、大纲、链接、历史，并执行模板、合并/提取和录音。
- macOS：“Notes”菜单与 `⌘⇧K` 打开知识库，`⌘⇧P` 打开命令面板；编辑区域的“笔记详情”提供知识管理入口；菜单可打开工作区管理。
- 知识库右上角操作菜单可新建 Canvas/Base、打开日记、创建笔记、打开命令和笔记库设置。文件仍为普通 `.md`、`.canvas` 和 `.base`，附件在 vault 中。
- 点击 Base 的普通顶层属性单元格进行修改；复杂字段使用笔记原始 YAML 编辑器。Base 的配置编辑器保存前先验证 YAML 和视图定义。

## 数据与性能边界

- 新的知识索引按需加载，按修改时间/文件大小复用未变笔记；不为建立关系图主动下载整个 iCloud vault。未下载及超过 2 MB 的笔记显示索引缺失提示，不会以完整结果误导用户。
- 全 vault 的重命名/移动与合并在后台准备。参与文档无法读取、非 UTF-8 或 Canvas JSON 损坏时会阻止操作；链接重写造成 YAML 失效时也拒绝操作，避免只移动文件而留下部分失效链接。大型或大量 iCloud 占位文档可能需要先下载。
- Base 表达式是有长度和递归限制的本地解释器，不执行 JavaScript 或 shell。YAML 属性/Base 文件限制 128 KB，JSON/YAML 值嵌套限制 64 层。
- 历史保存在 `.clipnest/history`。这会增加 vault 占用和同步量；上限是每文档 50 个版本，当前尚无历史总空间上限。
- 对外云同步、发布托管、社区插件兼容运行时、主题/CSS 插件和网页正文剪藏没有在本轮实现。现有 iCloud 文件夹支持不等同于 Obsidian Sync。网页提取协议仍是预留接口，不能宣传为完整网页正文抓取。
